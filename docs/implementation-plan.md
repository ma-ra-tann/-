実装計画

技術スタック
- バックエンド: C# / xUnit
- LLMエージェント: Python / Claude SDK
- フロントエンド: HTML / CSS / TypeScript
- データ: SQLite / JSON

TDDサイクル
1. レッド: 失敗するテストを1つ書く
2. グリーン: 最速でテストを通す（罪を犯してもよい）
3. リファクタリング: 重複を除去する

実装順序: ドメイン → ユースケース → ポート → アダプター

---

Phase 1: ドメイン層

1-1. VCファンド
  - VC名、WebサイトURL、投資ステージ、投資テーマを持つ
  - キャピタリストを0件以上持つ

1-2. キャピタリスト
  - 氏名、役職、投資担当領域を持つ
  - 財務モデル関心度を1つ持つ

1-3. 財務モデル関心度
  - ステータス（あり/不明/なし）を持つ
  - 根拠を0件以上持つ

1-4. 根拠
  - 種別（投資実績/発言/記事/登壇）、内容要約、情報ソースURLを持つ

---

Phase 2: アプリケーション層（ユースケース）

2-1. VC会社情報を補完取得する
  - VC名を受け取り、Web検索ポートで情報を取得し、VCファンドを生成して返す

2-2. キャピタリストを抽出する
  - VCファンドを受け取り、Web検索ポートでキャピタリスト情報を取得し、キャピタリスト一覧を返す

2-3. 財務モデル関連性を分析する
  - キャピタリストを受け取り、Web検索ポートとLLM分析ポートで根拠を収集して返す

2-4. 財務モデル関心度を判定する
  - キャピタリストと根拠を受け取り、LLM分析ポートで関心度（あり/不明/なし）を判定して返す

---

Phase 3: ポート（インターフェース定義）

3-1. 入力ポート
  - IVCリスト処理ポート: VC検索、キャピタリスト一覧取得
  - Iキャピタリスト閲覧ポート: キャピタリスト詳細取得

3-2. 出力ポート
  - IWeb検索ポート: VC情報検索、キャピタリスト検索、根拠検索
  - ILLM分析ポート: 根拠分析、関心度判定
  - Iデータ永続化ポート: 保存、取得

---

Phase 4: アダプター

4-1. 出力アダプター（先に実装）
  - Web検索アダプター: Google/Bing API
  - LLMアダプター: Claude SDK (Python)
  - DBアダプター: SQLite / JSON

4-2. 入力アダプター
  - Web UI: HTML/CSS/TypeScript
